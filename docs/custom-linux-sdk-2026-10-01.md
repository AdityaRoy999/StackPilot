Agents can build a private Linux SDK image from their task's bounded source Dockerfile, then use the observed digest for actual command execution. A build result is command evidence (`verified: false`), not application acceptance or deployment success.

The broker supplies the run, task, user, owner and attempt identities. The helper checks the live lease before staging, before execution, every two seconds while building, and before accepting the resulting image. Timeout (1–900 seconds), cancellation, nonzero Docker exit, missing digest or mismatched ownership labels reject the SDK and remove its generated tag.

Only inventoried regular source files are copied, with symlinks, special files, directory escapes and changed source rejected. The existing worker inventory caps source at 20000 files/256 MiB. Git metadata, dependency directories and platform runtime helpers are omitted; executable bits are preserved. Docker CLI configuration and environment are isolated. No control-plane environment, Git/cloud/registry credentials, secret/SSH inputs, build arguments or host mounts are supplied to the guest build. Network execution requires the operator's worker-network capability. Offline builds also reject remote ADD inputs, custom Dockerfile frontends, network overrides, unresolved base references and unavailable local base images.

Success includes the actual `sha256` image identity observed from Docker and labels `stackpilot.agent-run`, `stackpilot.agent-task` and `stackpilot.agent-sdk=true`. Command admission must match the requesting run to those observed labels. The shared local Docker daemon is a development adapter, not a hostile-tenant VM isolation guarantee. EC2 provisioning and a hardened remote build executor remain separate work.

Cleanup interface: `python agent_image.py cleanup REQUEST_JSON RESULT_JSON`, where the request contains `run_id`. This helper is trusted control-plane code. The broker verifies the caller owns the run and that the run is terminal/canceled before invoking it; an old task lease cannot authorize terminal cleanup. Cleanup filters by run and SDK labels, rechecks actual image ownership, retains any image referenced by a container, and uses no forced removal. Docker refuses a raced-in container reference. Retained, foreign, multiply-tagged or budget-deferred images are reported instead of claiming complete cleanup. The runtime scheduler reconciles terminal SDKs in a separate background task, with persistent claims and bounded retries; it does not block agent task claims.
